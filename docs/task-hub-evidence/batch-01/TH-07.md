## 5. Hướng dẫn chạy Demo thủ công (Manual Demo Flow)

Quy trình chạy demo end-to-end với dữ liệu thật trên PostgreSQL demo `wap_g1`:

1. **Build toàn bộ project trước khi chuẩn bị hoặc chạy:**
   ```powershell
   npm run build
   ```
2. **Khởi động Docker containers (PostgreSQL 55432, Redis 56379):**
   ```powershell
   npm run db:up:g1
   ```
3. **Áp dụng migrations lên database `wap_g1`:**
   ```powershell
   npm run db:migrate:g1
   ```
   *(Lưu ý: Trong các lượt test tự động vừa qua, hệ thống chỉ chạy trên DB tạm `engine_it_*`, chưa áp dụng lên `wap_g1`. Chạy lệnh này sẽ áp dụng migration 0004 mà không làm mất dữ liệu hiện có).*
4. **Seed dữ liệu mẫu:**
   ```powershell
   npm run db:seed:g1
   ```
   *(Lưu ý: `seedDemo` dùng `ON CONFLICT DO NOTHING`. Nếu card `c1` đã được chuyển sang `Done` trong lần demo trước, lệnh này **không đặt lại** `c1` về `Doing`).*
5. **Chuẩn bị plan chuyển card và gán biến định danh từ JSON prepare:**
   ```powershell
   $prepareJson = node packages/engine/dist/cli.js prepare testdata/dev-hand-plans/th-move.json
   if ($LASTEXITCODE -ne 0) { throw 'Prepare failed; inspect the error before continuing.' }
   $prep = ($prepareJson -join "`n") | ConvertFrom-Json
   $runId = $prep.run_id
   $approvalId = $prep.approval.id
   $versionId = $prep.workflow_version_id
   $snapshotHash = $prep.approval.snapshot_hash
   ```
6. **Xem trước (Preview) chi tiết các hành động bằng `$runId`:**
   ```powershell
   npm run engine -- preview $runId
   ```
   *(Lệnh `preview` trả về `{ run_id, actions, snapshot_hash }` — không chứa `approval_id`; do đó `$approvalId` được lấy từ JSON của lệnh `prepare` ở bước 5).*
7. **Phê duyệt chính xác 4 positional arguments từ `$prep` theo hợp đồng CLI:**
   ```powershell
   npm run engine -- approve $runId $approvalId $versionId $snapshotHash
   ```
   *(Lưu ý: CLI `packages/engine/src/cli.ts` nhận đúng 4 positional arguments, không dùng các cờ `--decision`, `--ids`, `--hash`).*
8. **Thực thi run đã duyệt:**
   ```powershell
   npm run engine -- execute $runId
   ```
9. **Kiểm tra trace kết quả thực thi các attempts:**
   ```powershell
   npm run engine -- trace $runId
   ```
   Lệnh `trace` xuất các attempt cùng `outcome_certainty` thực tế; với demo thành công, mong đợi ba attempt `confirmed`. Các trường hợp mất phản hồi/crash vẫn giữ `unknown` trong trace. Xác nhận thẻ `c1` đã chuyển sang `Done`, thông báo `"Đã chuyển Viết API sang Done."` được ghi vào `#team`.
10. **Đối chiếu và kiểm tra các bản ghi receipt trong DB:**
   ```powershell
   npm run engine -- reconcile $runId
   ```
   Lệnh `reconcile` (chỉ đọc) đối chiếu receipt và kiểm tra 2 receipts đã commit trong DB; không coi `trace` là bảng kết xuất trực tiếp các hàng receipt.
