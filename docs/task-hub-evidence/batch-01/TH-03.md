## Deviations và các sự cố đã xử lý

1. **Sự cố ghi đè historical evidence do thiếu `ATI_EVIDENCE_DIR` ban đầu và phục hồi:**
   - Trong một số lệnh test trực tiếp ban đầu của turn trước, biến môi trường `ATI_EVIDENCE_DIR` không được truyền vào process Node con, dẫn đến việc observation tests ghi đè nhầm vào `docs/g1-evidence/2026-09-13/mcp-observations.json` và `docs/engine-evidence/2026-09-13/controller-observations.json`.
   - **Biện pháp khắc phục đã thực hiện:** Bản ghi bị ghi đè nhầm đã được sao lưu vào `docs/task-hub-evidence/batch-01/TH-03/` để lưu chứng cứ. Sau đó, các file lịch sử bị ảnh hưởng đã được phục hồi chính xác theo từng byte từ `HEAD` (commit `3f68eaf`). Toàn bộ 26/26 file historical evidence + 3 migrations sha256 đã được xác minh bằng script khớp 100% với baseline handoff. Mọi lệnh test tiếp theo đều được chạy với `cmd /c "set ATI_EVIDENCE_DIR=docs/task-hub-evidence/batch-01/TH-03&& ..."` để ghi đúng stdout/stderr/exit code và observations vào `TH-03/`.
2. **Trình tự sync catalog sớm hơn schema equality assertion:**
   - Script `sync-catalog.mjs` đã được chạy sau khi có targeted receiver green ban đầu, nhưng trước khi test live discovery bổ sung assertion so sánh chi tiết `inputSchema` và `outputSchema` cho từng tool với `toolDefinitions()`.
   - **Xử lý:** Đã bổ sung đầy đủ assertion so sánh schema từng tool vào `tests/tools.integration.test.ts`, chạy lại targeted tests (13/13 passed), chạy lại deterministic sync, và chạy full `check:engine` đạt 96/96 passed.
3. **Thử nghiệm fixture emoji vs Zod 4 và tách test schema corruption:**
   - Ban đầu thử nghiệm fixture emoji 251 ký tự (`'😀'.repeat(251)`) để kiểm tra lỗi schema mà không cần drop DB constraint, dựa trên giả định `z.string().max(500)` kiểm tra UTF-16 code units (JS length = 502). Tuy nhiên, trên phiên bản Zod 4 hiện tại, string max được đo theo Unicode code points (`util.codePointLength = 251`), nên Zod vẫn chấp nhận chuỗi này.
   - **Xử lý:** Không thay đổi production contract `contracts.ts` (xóa bỏ `refine`, giữ nguyên `title: z.string().min(1).max(500)` như TH-02). Tách riêng test corruption: trong DB test suite tạm, tạm DROP `hub_cards_title_check`, insert title rỗng, gọi `get_card` và `list_cards` nhận `INTERNAL_ERROR`, và dùng khối `finally` để xóa record lỗi và ADD LẠI constraint chính xác theo migration 0004, kèm assertion kiểm chứng constraint đã phục hồi đầy đủ, không để schema yếu cho các test sau.
