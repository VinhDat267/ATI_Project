## Kết quả

- Gateway định tuyến bắt buộc theo `{server, name}`; hai server có thể cùng khai báo một tên tool mà không bị fallback hoặc gọi nhầm server.
- Connector `task_hub` đã được tách thành `gateway-task-hub.ts`; façade composite giữ nguyên launch tám tool cũ khi không có filesystem config.
- Startup/cleanup dùng `allSettled`: lỗi mở hoặc đóng một connection không làm bỏ sót cleanup connection khác.
- `ToolSchema.server` mở rộng đúng hai giá trị `task_hub | filesystem`, không đổi format snapshot `b-local-preview-1`.
- Receiver mode là mapping đóng, fail-closed:
  - bốn write task_hub với `b-local-1` → `local_transaction`;
  - filesystem `write_file` với `b-local-fs-1` → `non_idempotent`;
  - read, tool lạ, server lạ hoặc policy drift → `REGISTRY_CHANGED`.
- `prepare` lấy mode từ registry trusted; `execute` kiểm tra lại mode trước khi claim; không đọc mode từ DSL/argument/annotation.
- `callStep` truyền target đầy đủ và worker context nội bộ; chỉ runtime timezone và authorization đi qua MCP metadata.
- Chỉ `BeforeDispatchError` được ghi nhận là `before_dispatch`; lỗi sau khi giao transport vẫn giữ certainty `unknown`. Receipt verification chỉ áp dụng cho `task_hub/local_transaction`.
- `reconcile` chỉ join receipt cho task_hub local transaction; filesystem non-idempotent trả `receipt: not_supported`, `result: null`, và receiver mode tương ứng.
