# WEB-01C — Sáu view trên dữ liệu mô phỏng: kế hoạch triển khai

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dựng sáu view (Đăng nhập, Tổng quan, Tạo yêu cầu, Lần chạy, Chi tiết lần chạy, Công cụ & kết nối) bằng React + Tailwind v4 + shadcn/ui + TanStack Query, chạy trên một “thế giới” dữ liệu mô phỏng khớp canvas “ATI Run Screens”, gồm đủ 14 trạng thái và luồng khôi phục chốt ngày 18/09.

**Architecture:** `core/` giữ logic thuần không import React: trình bày trạng thái, tóm tắt thao tác ghi, nhóm lịch sử, luồng khôi phục, nháp yêu cầu trong bộ nhớ và query options. `fixtures/` là `Transport` mô phỏng nhiều lần chạy. `app/` chứa shell, route và view React; component chỉ gọi hook Query, không gọi `Transport` trực tiếp ngoài mutation. Tailwind `@theme` là nguồn token duy nhất, sinh từ DESIGN.md.

**Tech Stack:** React 19.3.0, TypeScript 5.9.3, Vite 8.3.0, Zod 4.6.2, Tailwind CSS 4.3.3, radix-ui 1.6.7, TanStack Query 5.103.1, lucide-react 1.47.0, Vitest 4.1.11, Playwright 1.63.0, @axe-core/playwright 4.13.0.

**Spec:** [platform UX](../specs/2026-09-15-platform-ux-design.md) (mục 3–4, các khối “chốt”), [DESIGN.md](../../../DESIGN.md), [ADR-002](../../ADR-002-FRONTEND-UI-DATA-LAYER.md), canvas “ATI Run Screens” (https://claude.ai/artifact/8eNa74zSxgGoAok87ePy2L) — mỗi view dưới đây ghi tên board tương ứng; board là nguồn bố cục và câu chữ.

Kế hoạch này **thay mục WEB-01C** của [2026-09-15-frontend-platform.md](2026-09-15-frontend-platform.md). Người dùng đồng ý triển khai ngày 18/09/2026 trên nhánh `feat/web-01c`, chấp nhận sửa sau; cổng “system design review” của plan cũ được ghi nhận là chưa đóng, không claim đã qua.

- Sáu view, bốn mục nav: “Tổng quan”, “Tạo yêu cầu”, “Lần chạy” (badge số cần xử lý), “Công cụ & kết nối”. Hash routes giữ nguyên `core/navigation.ts`.

Không thêm router/state/form/animation library, không font hay CDN từ xa.
- Token chỉ khai báo trong `apps/web/src/app/theme.css` bằng `@theme`. Không dùng arbitrary value màu/spacing (`bg-[#…]`, `p-[13px]`) trong view/component; ngoại lệ có comment lý do.
- Font: stack `'Be Vietnam Pro', 'Segoe UI', system-ui, -apple-system, Roboto, sans-serif` như DESIGN.md, **không tải Google Fonts** (ADR-002). Tự host Be Vietnam Pro để sau, ghi vào mục “Còn mở”.
- Budget WEB-01C: JS ban đầu ≤ 200 KiB gzip, CSS ≤ 30 KiB gzip.
- Token phiên chỉ trong bộ nhớ; URL chỉ chứa route và run id; nháp yêu cầu điền sẵn khi khôi phục nằm trong bộ nhớ, không vào URL.
- Mutation (`login`, `create`, `decide`, `cancel`) `retry: 0`, không optimistic update. Query key có `sessionGeneration`; đổi phiên thì `cancelQueries()` rồi `clear()`.
- Không `dangerouslySetInnerHTML`; payload hiển thị bằng text children.
- Không có nút retry/resume/replay/“đã giải quyết” cho thao tác ghi chưa rõ kết quả. “Tạo lại” chỉ điền sẵn yêu cầu mới (DESIGN.md mục Recovery).

```ts
// draft.ts — nháp trong bộ nhớ của tab, không URL/storage
export type OriginReason = "reconcile_seen" | "reconcile_not_seen" | "reconcile_confirmed" | "expired" | "failed" | "needs_input";
export interface RequestDraft { prompt: string; origin: { runId: string; reason: OriginReason } | null; }
export interface DraftStore { get(): RequestDraft | null; set(draft: RequestDraft): void; take(): RequestDraft | null; clear(): void; }
export function createDraftStore(): DraftStore;

// recovery.ts
export type RecoveryPlan =
  | { kind: "question"; prompt: string; options: RecoveryOption[]; note: string }
  | { kind: "primary"; label: string; note: string; draft: RequestDraft; secondary: { label: string; draft: RequestDraft | null } | null }
  | { kind: "none" };
export interface RecoveryOption { id: "seen" | "not_seen" | "differs"; label: string; effect: string; draft: RequestDraft | null; }
export function recoveryFor(run: RunDetail, receipts: ReconciliationReceipt[] | null, messageOnlyPrompt: string | null): RecoveryPlan;
type ReconciliationReceipt = "confirmed" | "conflict" | "not_observed" | "not_supported";
```

Quy tắc (DESIGN.md mục Recovery):
- `reconciliation_required`: mọi receipt `confirmed` → `primary` “Tạo yêu cầu chỉ gửi thông báo”, draft `{prompt: messageOnlyPrompt, origin reconcile_confirmed}`, note “Điền sẵn tin nhắn báo nhóm. Các dòng đã có sẽ không bị ghi lại.”; nếu `messageOnlyPrompt === null` (kế hoạch không có bước gửi tin) → `primary` “Tạo yêu cầu mới” với draft `null`-prompt rỗng. Có `conflict` → `question` 3 đáp án (`seen` “Đã thấy, đúng như đã gửi”, `not_seen` “Không thấy”, `differs` “Thấy nhưng khác nội dung”, draft `null`). Còn lại → `question` 2 đáp án (`seen` “Đã thấy đủ các dòng”, `not_seen` “Không thấy”). Note: “Câu trả lời chỉ dùng để điền sẵn yêu cầu mới. Lần chạy này vẫn ở trạng thái “Cần đối chiếu”.”
- `expired` → `primary` “Dùng lại yêu cầu này”, note “Hệ thống đọc lại dữ liệu và lập bản xem trước mới”, secondary “Tạo yêu cầu trống”.
- `failed` → như `expired`, note “Mở màn tạo với câu cũ để bạn sửa trước khi gửi”.
- `needs_input` → `primary` “Dùng câu gợi ý này” chỉ khi có câu gợi ý; ở WEB-01C câu gợi ý = `source_prompt` + `" "` + câu trả lời mẫu từ fixture world (`suggestedPrompt` trong world); nếu không có → `primary` “Dùng lại câu gốc”. Secondary “Dùng lại câu gốc” khi primary là gợi ý.
- `refused` → `none` (view hiện “Tạo yêu cầu mới” thường). Status khác → `none`.
- `messageOnlyPrompt` tính bởi `messageOnlyPromptFor(run)`: lấy bước `send_slack_message` trong plan, trả `Báo vào ${channel} rằng ${text đã chuẩn hoá bỏ dấu chấm cuối}`; không có → `null`.
