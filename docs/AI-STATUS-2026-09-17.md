## Verified starting point

- `PlannerPort` is the engine seam; the engine parses `PlannerResultSchema`,
  validates the returned plan against the reviewed gateway, performs the
  read-only preview and creates the approval snapshot.
- `DEV_FIXTURE_PLANNER` is server-owned and accepts only the reviewed fixture
  prompts. It is lifecycle evidence, not AI evidence.
- Prompt builders already define planning, bounded repair, query expansion and
  local-replan language. Prompt text does not replace engine validation or
  policy checks.
- The reviewed runtime catalog is 8 `task_hub` tools plus 2 optional
  `filesystem` tools. Retrieval must consume this reviewed snapshot, never raw
  MCP annotations or arbitrary client-supplied launch data.
- Migration `0007` adds a separate `reviewed_*` catalog/index store: it never
  queries the historical raw `tools` table. A complete 8+2 snapshot plus
  matching provider/model/dimensions/preprocessing/content/catalog hashes is
  required before atomic activation. The API can query an existing active index
  when an explicit semantic variant is selected, but it does not auto-populate
  or rebuild that index during startup or ordinary planning.
