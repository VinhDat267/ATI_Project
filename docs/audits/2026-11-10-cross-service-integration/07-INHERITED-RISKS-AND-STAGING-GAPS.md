## 1. Allowed Origin Taxonomy & Gate Impact Rules

Every entry in this register uses the mandatory 9-field schema (`ID`, `severity`, `origin`, `evidence`, `impact`, `service`, `owner`, `action`, `codegate` / `merge` / `prod`) and classifies `origin` strictly within the six normative categories:
1. `INTEGRATION-INTRODUCED` — Defect or contract mismatch arising from combining PR `#313`, PR `#314`, PR `#306`, and `origin/main` shared runtime paths.
2. `INHERITED FROM SHEETS` — Pre-existing architectural trade-off, UI/disclosure gap, or bounded limitation carried from Sheets R2 PR `#306` / baseline.
3. `INHERITED FROM TRELLO` — Pre-existing architectural trade-off or bounded limitation carried from Trello Combined PR `#313`.
4. `INHERITED FROM CALENDAR` — Pre-existing architectural trade-off or bounded limitation carried from Calendar Combined PR `#314`.
5. `STAGING EVIDENCE GAP` — Unverified behavior requiring real external OAuth/provider sandboxes, live LLM endpoints, or multi-instance staging infrastructure.
6. `PRODUCT VALIDATION GAP` — End-user workflow comprehension, adoption, ROI, or multi-service product scope criteria (normative v3 spec §1.4) outside automated technical integration tests.
