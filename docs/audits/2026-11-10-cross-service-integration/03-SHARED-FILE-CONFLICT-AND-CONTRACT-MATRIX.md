## 2. Intended Combined Behavior (Defined BEFORE Conflict Resolution)

Textual mergeability does not establish semantic correctness. Before any merge or conflict resolution occurs in Task B, the combined tree MUST simultaneously satisfy the following ten cross-service behavioral contracts:

### 2.1. Scheduler Claims, Admission, Post-Claim State Preservation & Startup Reconciliation
1. **Single-winner admission & claim serialization:** `ScheduleRunner.tick` and `startRun` (`apps/chat-api/src/services/schedules/schedule-runner.ts`) claim due `schedule_runs` atomically on PostgreSQL (`FOR UPDATE`), ensuring two independent OS scheduler processes never double-execute or double-deliver the same run.
2. **Pre-outbound delivery durability (`delivery_started_at`):** Every digest runner (`SheetsDigestRunner`, `TrelloDigestRunner`, `TelegramDigestRunner`, `CalendarDigestRunner`) commits `schedule_runs.delivery_started_at = now()` to PostgreSQL **before** issuing the outbound Slack/Telegram/Gmail HTTP request.
3. **Re-entry prevention:** `ScheduleRunner.startRun` refuses to re-enter execution when `run.delivery_started_at != null` (returning `null`) and idempotently reuses an existing `conv_id` and `schedule_run` user message if a prior pre-delivery planning attempt crashed after creating them (`TRELLO-AUDIT-15`).
4. **Post-claim pause / cancel / version-change / shutdown preservation (`GAS-04` + `TRELLO-AUDIT-15`):**
   - Once `delivery_started_at` is set or outbound delivery has succeeded (`outcome.status === 'digest_sent'` / `outcome.state === 'digest_sent'`), concurrent `pause`, `cancel`, schedule `version` bump, or runner `stop()` MUST NEVER overwrite the run into `'discarded'` or `'interrupted'`.
   - Confirmed provider receipts commit `status = 'digest_sent'`, `delivery` JSONB, and the corresponding `*_digest_sent` conversation message across `sheets_digest`, `trello_digest`, `telegram_digest`, and `calendar_digest`.
   - Ambiguous post-claim failures/timeouts/shutdowns commit `status = 'needs_attention'` with the service-specific `*_DELIVERY_UNKNOWN` marker (`SHEETS_DELIVERY_UNKNOWN`, `TRELLO_DELIVERY_UNKNOWN`, `TELEGRAM_DELIVERY_UNKNOWN`, `CALENDAR_DELIVERY_UNKNOWN`, `GITHUB_DELIVERY_UNKNOWN`).
5. **Startup crash reconciliation (`reconcileScheduleRuns`):** On process restart, `reconcileScheduleRuns` transitions stale `status = 'planning'` rows:
   - Rows with `delivery_started_at IS NULL` become `'interrupted'` (no outbound send occurred; never auto-replayed silently).
   - Rows with `delivery_started_at IS NOT NULL` become `'needs_attention'` with service-specific error markers via the `schedules.kind` `CASE` expression (`sheets_digest` -> `SHEETS_DELIVERY_UNKNOWN`, `trello_digest` -> `TRELLO_DELIVERY_UNKNOWN`, `telegram_digest` -> `TELEGRAM_DELIVERY_UNKNOWN`, `github_digest` -> `GITHUB_DELIVERY_UNKNOWN`, fallback `calendar_digest` -> `CALENDAR_DELIVERY_UNKNOWN`), preserving existing `*_DELIVERY_UNKNOWN` text when already recorded.

### 2.2. Trusted Workspace, Active Identity, Pinned Credentials & Resource Allowlists
1. **Authoritative DB workspace scope:** Digest runners and `ScheduleService` derive `workspaceMode` and `workspaceId` strictly from persisted `schedules` / `conversations` rows (`resolveTrustedScheduleScope`, `assertDigestScheduleLiveScopeAndAuth` in `apps/chat-api/src/services/schedules/digest-scope-guard.ts`), never from untrusted caller headers or mutable in-memory defaults.
2. **Active user & org membership gate:** Before any source read AND again immediately before outbound send (`TRELLO-AUDIT-07`, `GAS-01..11`, `CALENDAR-REM-A`), `users.status = 'active'` and (for `organization` mode) `workspace_members.status = 'active'` are re-verified; revoked/inactive principals abort with `0` outbound sends and transition the schedule to `paused` / run to `blocked`.
3. **Fail-closed organization `AdapterFactory` scope:** `AdapterFactory.getAdapterForService` (`apps/chat-api/src/services/adapter-factory.ts`) rejects `context.workspaceMode === 'organization'` when `context.workspaceId` is missing/blank across both generic workspace credentials and Trello personal/org scope resolution, and never falls back to personal credentials or legacy shared (`user_id IS NULL, workspace_id IS NULL`) rows in personal/organization modes.
4. **Service-specific resource & path allowlists:**
   - **Trello (`#313`):** Strict `TRELLO_RESOURCE_ID_PATTERN` (`^[A-Za-z0-9_-]{1,64}$`) at both `@wap/tool-schemas` and `TrelloBase` (`packages/tool-adapters/src/trello/base.ts`) blocks `..`, `/`, `?`, `#`, `%`, backslashes, and whitespace with `0` HTTP requests (`requestSent: false`); `trello.get_card` and `trello.search_cards` verify minimal `/1/cards/:id?fields=id,idBoard` or `/1/lists/:id?fields=id,idBoard` against `allowedBoards` before fetching checklists or list cards; `create_card` / `update_card` / `add_member` verify target board membership before mutating.
   - **Google Sheets (`#306`):** `PersonalSheetsAdapter` and `SheetsAdapter` enforce `allowedScope.spreadsheets`; `analyzeSheetsDigestCandidate` and `verifySheetsDigestCandidateInTx` canonicalize explicit A1 ranges (`GAS-05`), reject unbounded/oversized ranges fail-closed, bind exact personal Gmail recipient or Slack/Telegram destination targets, and verify pinned source + destination credentials in transaction.
   - **Google Calendar (`#314`):** `PersonalCalendarAdapter` enforces `allowedScope.calendars` (`allowedCalendars`), rejects cross-calendar access with `0` provider writes, and propagates explicit IANA `timeZone` (`IANA_TIMEZONE_PATTERN`) across read, free-slot, conflict-precheck, and recurring event write paths.

### 2.3. Delivery Receipts, Unknown Outcomes & No-Replay Guard
1. **Strict provider receipt validation (`SlackAdapter.sendMessage`, Telegram, Gmail):**

Any `ok: true` response with missing, numeric (`12345`), object (`{}`), empty, or `'undefined'`/`'null'` `ts` or `channel` MUST throw `StepError` (`packages/tool-adapters/src/base-adapter.ts`) with `category: 'UNKNOWN'`, `retryable: false`, and `details: { requestSent: true }` (note: `StepError` has `{ message, category, statusCode?, retryable?, details?, cause? }` and no `code` field; do not assert nonexistent error symbols).

PR `#313` replaced that with `typeof res?.ts === 'string' ? res.ts.trim() : ''`, checked `rawTs === 'undefined'` and `rawChannel === 'undefined'`, and set `details: { requestSent: true }`, **but** fell back to `args.channel` when `res.channel` was missing/non-string/empty (`typeof res?.channel === 'string' && res.channel.trim() ? res.channel.trim() : args.channel`) and did not reject `'null'`.
